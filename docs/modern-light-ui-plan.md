# DiskCleaner 浅色现代化界面方案

制定日期：2026-11-02。修订：根据用户偏好，转向当前 AI / Agent 产品的浅色工作台视觉。状态：已实施；下文保留设计目标，实际交付与检查结果见 `modern-light-ui-validation.md`。

## 1. 推荐方向

采用 **紧凑型 AI 工作台风格浅色界面**：暖中性的近白背景、白色内容区、炭黑主操作、统一线性图标、低对比度分区。借鉴 Claude 的柔和表面、Cursor 的紧凑工作区和 Codex 的任务组织方式。列表与空间图占据主要面积。

视觉方向以本次用户修订为准，替代此前的蓝色主按钮与 Fluent 外观定位。技术实现仍可使用 Qt Widgets；视觉参考不受底层控件框架限制。

技术上保留 C++20 + Qt 6 Widgets，建立覆盖全界面的样式与组件层：QPalette + QSS + 必要的组合控件和绘制委托。所有可见控件都纳入设计，包括弹窗、菜单、复选框、滚动条和下拉列表。

现代化的验收依据是完整的视觉及交互规范：正常、悬停、按下、选中、键盘焦点、禁用、错误状态均一致；底层可继续使用成熟的 Qt 控件类。

## 2. 当前依据

- `CMakeLists.txt`：现有程序使用 Qt Widgets、Network，没有 Qt Quick 界面依赖。
- `src/theme.cpp`：已有 Fusion、浅色调色板和全局 QSS；按钮、输入框、Tab、表格等已有基础样式。
- `src/mainwindow.cpp`：目录树、文件列表、自绘百分比、筛选、多位置扫描、导出选项、空间图设置等界面已具备。
- `src/treemap.cpp`：空间图使用 QPainter 绘制，面积与数据和统计口径绑定。
- 已查看保存的 `work/compact-ui/after.png`。此次未重新运行应用，截图与当前运行状态可能有差异。
- `design-qa.md` 记录了此前压缩摘要、Tab、控件和状态栏的要求。本方案沿用紧凑方向，以该记录作为设计约束。

现阶段主要问题：应用操作图标仍带有平台默认样式；分段选择像相邻独立按钮；复选框、数字步进器、滚动条等缺少完整统一规范；空间图导航重复显示路径；浅色基础虽已存在，但弹出层与细节状态仍需要整体补齐。

## 3. 技术路线取舍

| 路线 | 收益与成本 | 结论 |
| --- | --- | --- |
| 只调整现有 QSS 的颜色和圆角 | 改动小；复杂控件、图标、组件结构和交互状态仍不统一 | 不足以达到本次目标 |
| Widgets + 完整主题 + 小型组件层 | 复用现有模型、键盘操作和业务连接；可分阶段覆盖全部控件 | 推荐 |
| 迁移 Qt Quick / QML + FluentWinUI3 | 可使用 Quick 的现代控件；需要迁移复杂表格、树、菜单、图表及测试连接 | 留作未来整体重构选项 |

Qt 官方 FluentWinUI3 属于 Qt Quick Controls，不能直接给 QWidget 切换该样式。其官方文档还列出部分控件回退 Fusion 的限制，因此迁移也不能自动解决全套控件的一致性。

本轮不预设第三方 UI 框架依赖。如后续要求使用现成组件库，应先核对 C++ Widgets 兼容性、授权、当前 Qt/MinGW 工具链和部署体积，再决定是否引入。

主操作使用炭黑填充；筛选和模式切换采用浅灰底座上的白色选中块，以文字字重与清楚的焦点共同区分状态。阴影只用于必要的浮层，面板分区优先通过表面色和细分隔线表达。正文和关键数值验收对比度目标为 4.5:1，焦点与关键非文本状态目标为 3:1；颜色值需在真实相邻背景上复核。上述颜色是本项目建议 token，并非从参考产品提取的官方色值。

## 5. 主窗口布局

保留原生 Windows 标题栏；把文件、选项、帮助组织为紧凑的应用菜单入口，保留快捷键与完整可访问性。保持主分析区左右分栏及可拖动分隔条。现有目录树承担左侧资源浏览职责，不额外叠加占宽的任务侧栏。

```text
DiskCleaner  [应用菜单]                                 [设置]
──────────────────────────────────────────────────────────
[磁盘 | 文件夹] [路径输入……………………] [浏览] [开始扫描]
本次扫描 · sample     磁盘占用 24.0 KB     所属磁盘容量与可用空间
──────────────────────────────────────────────────────────
[空间分析] [文件列表]           统计口径 [文件大小 | 磁盘占用]
┌ 目录占用 ─────── [搜索] ┐  ┌ 空间分布 ───────── [选项] ┐
│ 名称 / 大小 / 占比 / 数量│  │ ← → ↑  根目录 > 当前目录  │
│                        │  │                          │
│ 可排序、可展开目录列表    │  │ 基于实际字节数绘制的空间图 │
│                        │  │                          │
└────────────────────────┘  └──────────────────────────┘
扫描状态 · 已选项目                         [打开位置] [复制路径]
```

- 路径输入保留完整路径编辑、粘贴和清除能力；窄窗口优先让输入区域伸缩。
- 顶部扫描控件组成一条连续工具区，弱化每个操作的独立方框。开始扫描使用炭黑主按钮，浏览和设置为低强调按钮。
- 扫描摘要继续区分本次扫描总量与所属磁盘容量。保留当前扫描、上次结果和失败状态标识。
- 「关于」归入帮助菜单，顶层 Tab 聚焦空间分析与文件列表。
- 文件类型保留按需展开入口，统一停靠面板标题和表格。浮动时的窗口外框由操作系统管理。
- 图表区域仅保留一组路径导航；面包屑末段优先显示，中间段可折叠到菜单，完整路径可复制。
- 层级与分类配色进入「图表选项」小面板，并在按钮提示中标明当前配置；高频导航常驻。
- 1080×680 下优先保留名称、大小、占比和文件数；较低优先级列允许横向滚动，功能入口不能消失。

## 6. 控件改造清单

| 范围 | 目标设计 | 实现原则 |
| --- | --- | --- |
| 按钮与工具按钮 | 主按钮、次按钮、纯图标按钮、危险按钮四种角色；所有状态统一 | 保留 QPushButton / QToolButton；用角色属性控制样式 |
| 扫描类型、统计口径 | 真正的一体式分段选择，统一容器与接缝 | 封装 QButtonGroup 与可选中按钮，保留键盘和互斥语义 |
| 路径和搜索输入 | 细边框、明确焦点、统一清除按钮和错误反馈 | QLineEdit 组合图标与操作；错误提示保留可读文字 |
| 下拉框与数字输入 | 统一箭头、下拉列表、悬停项、禁用项和步进按钮 | 完整定义 QComboBox / QSpinBox 子控件，不能只改外框 |
| 复选框、单选框 | 统一 16px 指示器和勾选图标；支持半选态 | 筛选仍用复选框；即时持久设置才考虑开关样式 |
| Tab | 紧凑文字导航、明确选中指示及键盘焦点 | 统一 QTabBar；隐藏页内容不占空间 |
| 树和表格 | 轻表头、弱分隔、清晰选中态、数值右对齐 | 保留 QTreeView / QTableView 与 model/view，不逐行创建控件 |
| 占比条 | 6px 低饱和强调色进度条，数值独立对齐 | 修改现有 PercentageDelegate；使用共享主题色 |
| 滚动条与分隔条 | 细滑块、足够命中区、可见的悬停和拖动态 | 完整覆盖横纵方向；滑块视觉宽 6–8、命中区约 12 |
| 菜单与提示 | 统一图标列、文字列、快捷键列和分隔线 | 统一 QMenu / QToolTip；全部功能和快捷键继续可达 |
| 进度与通知 | 扫描进度嵌入摘要，轻量成功消息不阻断操作 | 未知总量用不确定进度，禁止显示虚构百分比 |
| 业务弹窗 | 统一标题、表单、说明、错误区域和底部按钮区 | 导出、多位置、图表设置等复用 DialogShell；删除保持明确确认 |
| 系统窗口 | Windows 原生标题栏、文件选择器 | 保留系统熟悉的操作与辅助能力，系统外框不强制套应用 QSS |

应用操作图标使用一套可随状态着色的矢量资源；文件类型图标可保留 Shell 提供的真实类型图标。矢量资源需检查许可证，打包时明确所需渲染插件，不能只在开发机可用。

## 7. 空间图与状态

- 保持稳定的分类色，以蓝、青、紫、橙等低饱和色区分；同一数据与模式下颜色稳定。
- 选中项使用清楚的细描边；悬停轻度提亮。颜色之外还要有标签、路径和大小说明。
- 父目录标题与叶子标签分层；小色块优先隐藏文字，通过提示查看详情。
- 所有装饰限制在已有单元格内；不改变面积计算、统计分母及小块隐藏规则。
- 空状态展示简短扫描指引；无搜索结果提供清除筛选；扫描失败保留上次结果及其归属。
- 动效只用于少量状态过渡，约 100–150ms；不为大量表格行和整个空间图增加持续动画，并尊重系统减少动画设置。

## 8. 建议代码组织与实施顺序

1. **主题和控件基线**：整理 `src/theme.h/.cpp`，建立颜色、字号、尺寸 token；将 QSS 按控件分段管理，加入资源与图标入口。用小型预览页覆盖正常、焦点、选中、禁用和错误状态。
2. **主界面应用**：在 `src/mainwindow.cpp` 接入分段控件、搜索框、导航与按钮角色；修改现有百分比委托；保留业务信号槽、对象标识和用户设置兼容性。
3. **空间图与次级界面**：在 `src/treemap.cpp` 统一绘制色、标签、选中状态；覆盖文件列表、筛选栏、类型面板、右键菜单、业务弹窗和空状态。
4. **验证与收尾**：扩展已有截图验证覆盖弹出层，运行现有回归和冒烟检查，保存同数据、同窗口尺寸的前后对照。

按实际需要新增 `src/ui/` 下的 SegmentedControl、PathInput、BreadcrumbBar、DialogShell 和共享图标入口；避免为已经能完整设定样式的每个 Qt 控件创建包装类。资源接入时更新 CMake。扫描、删除、实时更新等核心逻辑不属于本次美化改动范围。

浅色作为此次设计和验收基线，新安装默认浅色；已有用户主题选择继续尊重。共享样式修改时必须确认旧深色入口没有被破坏。

## 9. 验收标准

- 主窗口、菜单、下拉、滚动条、复选框、数字输入和业务弹窗视觉统一；系统拥有的窗口外框明确例外。
- 1486×1024 与 1080×680 逻辑尺寸可用，验证 100%、125%、150%、200% DPI；中文、英文、长路径和长文件名不遮挡关键操作。
- 同尺寸默认状态下，分析面板可用高度以当前紧凑版为基线，目标下降不超过 16 逻辑像素；每行仍为 26 逻辑像素，字体需要更高行高的可访问配置除外。
- Tab 顺序、空格勾选、方向键导航、菜单快捷键和焦点指示完整。不能为美观去掉焦点且没有替代指示。
- 扫描、取消、筛选、排序、选择同步、文件类型面板、导入导出及设置保存通过原有回归；删除确认采用测试替身验证，不用真实文件做破坏性验收。
- 应用菜单收拢后，原有文件、选项、帮助操作及键盘入口仍完整可达。
- 空间图真实面积比例、大小口径和扫描范围分母保持现有测试结果。
- 同一大型结果集对比滚动与窗口缩放响应，记录数据规模和观察结果；避免全表重绘、逐行 QWidget 和高频全局 QSS 重设。

## 10. AI / Agent 产品参考与落地边界

调研日期：2026-11-02。以下选择基于与本项目的适配程度，不表示市场热度排名，也不声称产品演示等同于所有账号的最新客户端。

| 参考来源 | 观察依据与可借鉴部分 | DiskCleaner 的具体采用方式 |
| --- | --- | --- |
| [Claude / Cowork](https://claude.com/product/cowork) | 已查看官方内置浏览器演示图：近白暖底、低对比度工具区、简洁图标，任务与工作内容左右并置 | 暖中性浅底、轻按钮、按需显示的辅助设置、清晰的内容区域 |
| [Cursor](https://cursor.com/) | 已查看官网实际渲染的 Desktop 演示：紧凑任务列表、细分隔、工作内容与操作并列 | 目录树和空间图组成连续工作区；减少边框套框；保持数据密度 |
| [Codex](https://openai.com/index/introducing-the-codex-app/) | 官方发布文档说明按项目组织任务、查看执行进度及审阅结果；该发布页为 2026-02-02 历史资料 | 以“扫描目标 → 执行状态 → 结果查看”为信息顺序，当前任务状态就地呈现 |

参考界面中的工作内容、示例网站和产品外侧宣传背景，不作为应用本身的配色依据。Claude 官方浏览器演示中的绿色网站及彩色定价卡属于被访问网页；本方案提取的是外围应用的浅色工具区。

本项目采用一个统一方向：**Claude 的柔和表面 + Cursor 的紧凑布局 + Codex 的任务信息层次**。这是设计建议，非这些厂商联合发布的设计规范。

具体调整重点：

1. 以少量表面色建立层次，削弱原先蓝色高亮遍布控件的感觉。
2. 数据表格使用紧凑行、统一数值对齐和适量留白，标题与工具按钮低强调。
3. 搜索、模式切换和图表选项形成简洁工具区；详细条件按需展开。
4. 扫描阶段、取消、失败原因和结果归属在同一位置连续呈现，信息有可追踪性。
5. 空间图保留必要的多色数据编码，其他界面区域保持克制。

此次范围为视觉与现有交互整理。AI 对话框、自然语言清理、自动删除建议、扫描历史、命令面板等新增能力不因参考 Agent 产品而自动加入。聊天页的大段留白和大尺寸输入框不适合本工具的结果页密度。

## 11. 官方技术依据

- [Qt Widgets 样式表参考](https://doc.qt.io/qt-6.11/stylesheet-reference.html)：支持控件状态和子控件样式；完整覆盖要包括下拉、指示器、滚动条等，并注意浮动 Dock 的限制。
- [Qt Quick Controls FluentWinUI3](https://doc.qt.io/qt-6.11/qtquickcontrols-fluentwinui3.html)：属于 Quick 控件体系；部分控件尚有回退限制。

以上为方案依据和设计目标。实施时保留原菜单栏及关于页，以保持既有操作入口；路径采用紧凑面包屑文字与祖先目录菜单。当前版本的验证证据与范围以 `modern-light-ui-validation.md` 为准。
